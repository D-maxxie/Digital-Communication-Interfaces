# 8-to-1 Multiplexer (16-bit) in Verilog HDL

## Overview

This project implements an **8-to-1 Multiplexer (MUX)** with **16-bit input and output buses** using a **hierarchical design**. The multiplexer is constructed entirely from **2-to-1 multiplexers (`mux_16`)**, making the design modular, scalable, and easy to understand.

The circuit selects one of eight 16-bit input signals according to a 3-bit select signal and forwards the selected input to the output.

---

# Features

- 8 independent inputs
- 16-bit data width
- 3-bit select signal
- Hierarchical implementation
- Built using 2-to-1 multiplexers
- FPGA-friendly modular design

---

# Module Description

## Module Name

```
mux_16_8
```

The module selects one of eight 16-bit inputs and sends it to the output.

| Signal | Width | Description |

| `i1` – `i8` | 16 bits | Input data |
| `s` | 3 bits | Select signal |

---

## Output

| Signal | Width | Description |
|--------|------:|-------------|
| `o` | 16 bits | Selected output |

# Internal Signals

Intermediate outputs generated by the first two stages:

```verilog
wire [15:0] x1, x2, x3, x4;
wire [15:0] y1, y2;
```

These signals connect the different levels of the multiplexer tree.

---

# Hierarchical Architecture

The design is composed of **seven 2-to-1 multiplexers (`mux_16`)**.

---

## Stage 1

Four multiplexers select between adjacent input pairs.

```
i1  i2  ---> x1

i3  i4  ---> x2

i5  i6  ---> x3

i7  i8  ---> x4
```

Selection is controlled by:

```
s[0]
```

---

## Stage 2

Two multiplexers select between the outputs of Stage 1.

```
x1  x2 ---> y1

x3  x4 ---> y2
```

Selection is controlled by:

```
s[1]
```

---

## Stage 3

The final multiplexer selects between the two remaining signals.

```
y1

y2

↓

Output
```

Selection is controlled by:

```
s[2]
```

# Selection Logic

The select signal determines which input reaches the output.

| Select (`s`) | Output |
|--------------|--------|
| 000 | i1 |
| 001 | i2 |
| 010 | i3 |
| 011 | i4 |
| 100 | i5 |
| 101 | i6 |
| 110 | i7 |
| 111 | i8 |

# Limitations

- Depends on the availability of the `mux_16` (2-to-1, 16-bit) module.
- Manual instantiation becomes cumbersome as the number of inputs increases.
- The design is fixed for eight inputs and sixteen-bit data unless modified.

---

# Coding Improvements

### 1. Parameterize the Data Width

Replace the fixed 16-bit width with a parameter:

```verilog
parameter DATA_WIDTH = 16;
```

and declare inputs and outputs using `DATA_WIDTH` to make the module reusable.

---

### 2. Use Generate Statements

The repeated `mux_16` instantiations can be created using `generate` loops in larger hierarchical designs to reduce repetitive code.

---

### 3. Adopt Named Port Connections

Instead of positional instantiation:

```verilog
mux_16 mux_16_1(x1, i1, i2, s[0]);
```

use named ports:

```verilog
mux_16 mux_16_1 (
    .o(x1),
    .i1(i1),
    .i2(i2),
    .s(s[0])
);
```

This improves readability and reduces the chance of connection errors.

---

### 4. Consider SystemVerilog Arrays

In SystemVerilog, the inputs can be represented as an array:

```systemverilog
input logic [15:0] data [0:7];
```

making the module cleaner and easier to scale.

---

### 5. Verify the Supporting Module

Ensure the `mux_16` module correctly implements a 2-to-1 multiplexer with 16-bit inputs and output, as the functionality of this module depends entirely on it.
